# 审计 SFT1/SFT2 调试至重训的工作流延迟

## Goal

只读重建 2026-08-26 至 2026-08-31 从 SFT1/SFT2 debug 到新一轮 SFT training 的实际时间线，区分技术工作、等待人类审批、重复/过度验证、旁支工作与不可见 Agent 活动所造成的延迟，并提出可执行的 Pi Agent + pi-app 工作流改进建议。

## Requirements

- 审计范围覆盖 2026-08-26 至 2026-08-31，与 SFT1/SFT2、state interface、query-state、训练准备和正式重训直接相关的任务、会话与提交。
- 检查 Trellis task artifacts、Git history、相关实验/训练记录、项目 journal，以及必要的本地 Pi 会话历史；原始会话召回仅作为线索，结论必须尽量由当前文件或提交证据复核。
- 建立按时间排序的关键事件、决策、审批请求、等待、测试/验证、返工、范围切换与训练启动节点。
- 尽可能量化各类延迟；证据不足时明确标为估计或未知，不虚构精确时长。
- 分开判断：
  - 项目安全规则要求的必要审批；
  - Agent 可通过提前批量请求、ask-before 合同或自主默认策略避免的审批等待；
  - 必要测试、重复测试、测试粒度不当及环境/基础设施耗时；
  - 多任务并行、worktree/storage 等旁支工作造成的上下文切换；
  - Pi Agent / pi-app 缺少进度可见性带来的体验问题。
- 改进建议必须按收益、风险和实施成本分级，并明确哪些只需调整使用方式，哪些需要修改 Trellis/project policy、Pi extension 或 pi-app。
- 最终报告保存于本任务 `research/`，并在对话中提供简明结论。

## Authorization and exclusions

- 人类已批准创建本只读审计任务。
- 除本任务自身的规划、上下文清单和最终审计报告外，不修改任何项目源码、配置、实验合同、历史任务、memory、训练数据、checkpoint、实验输出或 Pi/pi-app 文件。
- 不启动、停止或修改任何训练、评估、GPU、Slurm、远程 job。
- 不 commit、push、merge，也不清理现有 dirty changes。
- 不把本次审计状态复制到 Pi TaskTree。
- 本任务不是实验任务，`meta.kind` 不设为 `experiment`。
