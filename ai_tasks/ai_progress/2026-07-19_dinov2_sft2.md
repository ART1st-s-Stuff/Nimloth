# 2026-07-19 DINOv2-aligned SFT2

## 任务目标

按人类要求启动一个实验名称明确包含 `dino` 的新 SFT2。由于服务器没有 DINOv3 权重访问且现有 Transformers 不支持 DINOv3，人类明确改为由 AI 选择 DINOv2，并要求使用多节点碎片凑满 8 GPU。

## 人类确认

- Teacher：选择公开 `facebook/dinov2-large`（ViT-L/14，hidden size 1024），与现有 WM state 1024 维直接对齐。
- 资源：多个节点的碎片 GPU，目标 world size 8。
- 实验身份必须明确写 DINO；记录中必须写明实际为 DINOv2，禁止称作 DINOv3。

## 实验前核查

- 目的：在保持正式 k=8 SFT2 其余语义不变时，增加 current RGB observation 的 frozen DINOv2 CLS 对齐，验证 query state 是否获得更强全局视觉语义。
- 代码分支：`feat/dinov3-query-alignment`；DINOv2 泛化改动尚待提交。
- 入口：`experiments/training/sft2/train.py` / `nimloth.training.sft2.trainer`。
- 初始化：`.../full_2e66e97/sft1/epoch_005/hf_merged`，config 与2个safetensors shard存在。
- 数据：`converted_strict_k8_b6c811c/train_all.jsonl` 为3217条、全部 `split=train`、唯一ID3217、success613；`val_all.jsonl` 为355条、全部 `split=val`、唯一ID355、success110。
- cache：复用正式 k8 run 的 compact cache；train 59,389 transitions，val 6,054；k=8/inject/masked/BF16/max_pixels100352，双manifest完整。DINO target读取 `current_image_path`，无需重建Qwen preprocess cache。
- W&B：project `nimloth-sft2`；最大数字ID=29，候选下一个ID=30，提交前必须再次查询避免并发占用。后续发现ID29已于20:25因het component实际8h walltime超时结束，W&B为crashed。
- 资源快照：normal 共15张空闲，单节点最多4；preempt共4张空闲。人类选择跨节点碎片 world size 8。

- DINOv2 config已从HF核实：`Dinov2Config hidden_size=1024, patch_size=14`。

## 训练/冻结模块

- Frozen：DINOv2 teacher、Qwen LLM。
- Trainable：Qwen vision encoder（full + EMA）、k=8 query embedding adapter、StateProjector、WM predictor、ValueHead。
- Loss：原 LM CE + WM MSE + SIGReg + value loss，并新增 `lambda_dino=1.0` 的 current-RGB CLS MSE。

## 计划参数

- k=8 / inject / query adapter。
- epochs=10, batch size=2。
- world size=8，grad accumulation=4（保持正式 k8 effective accumulation）。
- max_pixels=100352，max_images_per_batch=12，best按 val WM MSE。
- normal partition，多节点碎片；预计约15–25小时，DINO额外forward的实际开销待健康启动后测量。
- checkpoint：每20分钟 latest、每epoch完整checkpoint、best/final；同一输出目录支持精确resume。
- 监控：total/LM/WM/SIGReg/value/DINO MSE、各组LR、finite检查、GPU显存/利用率、checkpoint完整性、W&B。
